# AIエージェント作業ガイドライン

更新日: 2026-07-06

## 基本姿勢

- いきなり大規模実装しない
- まず最小構成で起動確認する
- 既存のコードスタイルとディレクトリ構成を尊重する
- 仕様は `dos/`、実装時の作業判断は `.ai/` を確認する
- 外部スキルや特定AIツールに依存しない作業手順は `.ai/workflows/` を確認する

## 実装時の注意

- README にセットアップ手順を書く
- `.env.example` を必ず作る
- API 型は `packages/shared` に置く
- 画像解析ロジックは `packages/vision` に分離する
- 他の農産物にも拡張できるよう `productId`、`varietyId`、`countUnit` で管理する
- AI 推定値と人間の修正値を分けて保存する
- Cloud Run 前提で backend を構築する
- Firebase に業務ロジックを寄せすぎない

## セキュリティ

以下は読取・変更禁止。

- `.env` 系ファイル
- `*/config/secrets.*`
- `src/env/*`
- `*.pem`
- `*.key`
- APIキーや認証情報を含むファイル全般

必要な環境変数は `.env.example` にキー名だけを書く。

## 開発ステップ

1. `dos/` の仕様を確認する
2. `.ai/requirements.md` を確認する
3. 作業種別に応じて `.ai/workflows/` の該当ファイルを確認する
4. `.ai/implementation-plan.md` に沿って小さく作る
5. 最小起動を確認する
6. README を更新する
7. 検証結果を報告する

## 判断に迷った場合

- 仕様に関わる内容は `dos/` を更新する
- AIエージェントの作業手順に関わる内容は `.ai/` を更新する
- 大きな設計判断は `dos/decisions.md` に残す
- 実装範囲が広がる場合は、実装前に計画を更新する
- プロジェクト固有の学びは `dos/learnings/` に残す
